# 动态板块管理与流畅 MathJax 预览设计

## 目标

将当前写死在 CMS 配置和 Hugo 菜单中的两个板块改造成可维护的板块注册表，使管理员可以在后台：

- 新增板块；
- 修改已有板块的显示名称；
- 为新板块填写稳定的英文 Slug；
- 设置导航排序；
- 使用与现有文章一致的标题、日期、草稿、评论、封面、正文等字段。

本次已确认的名称变更为：`二次元与随笔` → `随笔`，Slug 继续保持 `acgn`，因此现有文章 URL 不变。

同时优化 CMS 的 MathJax 预览，优先保证大量公式文章在编辑时的输入流畅性，允许公式延迟约 500ms 至 1s 渲染，但最终仍自动完成渲染。

## 非目标

- 不支持本次直接删除板块；删除板块需要单独处理其中的文章和旧 URL。
- 不支持修改已经使用的板块 Slug；如果检测到会导致目录或 URL 改变，构建必须失败并给出明确错误。
- 不增加正文 Markdown 或 LaTeX 示例提示。
- 不增加手动“渲染公式”按钮。
- 不改变现有 GitHub OAuth、Sveltia 登录和文章公开 URL。

## 板块数据模型

使用 `data/sections.json` 作为板块注册表，避免把名称、菜单和 CMS 集合重复维护在多个文件中：

```json
{
  "sections": [
    {"name": "学术推导与笔记", "slug": "math", "weight": 10, "math": true},
    {"name": "随笔", "slug": "acgn", "weight": 20, "math": false}
  ]
}
```

字段约束：

- `name`：必填，作为网站导航、板块首页和 CMS 集合名称；
- `slug`：必填且唯一，只允许小写英文、数字和短横线，创建后保持稳定；
- `weight`：必填整数，数字越小越靠前；
- `math`：控制该板块新文章的公式默认值，现有数学板块保持开启，新板块默认关闭。

板块注册表将通过 Sveltia 的固定“板块管理”文件集合编辑。新增或重命名后，构建脚本从注册表生成其余消费者。

## 生成流程

新增 `scripts/sync_sections.py`，在本地验证和 GitHub Pages 构建中运行：

1. 读取并校验 `data/sections.json`；
2. 检查 Slug 合法性、唯一性、排序数字和既有内容目录一致性；
3. 为每个板块生成或更新 `content/<slug>/_index.md`，写入板块名称和 `menu.main` 的排序信息；
4. 根据同一注册表生成 `static/admin/config.yml`；
5. 为每个板块生成一个 CMS 文章集合，使用统一字段和该板块的目录；
6. 保持 `content/_index.md` 主页文件不受影响。

生成的 CMS 配置应包含：

- 固定的“板块管理”集合；
- 动态生成的“学术推导与笔记”“随笔”以及未来新板块集合；
- 统一文章字段：标题、日期、数学开关、草稿、评论、封面和正文；
- 板块名称显示使用注册表的 `name`，文章目录使用稳定的 `slug`。

`static/admin/config.yml` 的生成结果不可手工维护；本地 README 和 CI 都必须先运行同步脚本，再执行 Hugo 构建。新板块即使暂时没有文章，也会由生成的 `_index.md` 提供正常板块页面。

## 名称修改与兼容性

当管理员将 `acgn` 的名称修改为“随笔”时：

- 网站导航显示“随笔”；
- `/acgn/` 板块首页标题显示“随笔”；
- CMS 集合名称显示“随笔”；
- `content/acgn/` 下的文章路径保持不变；
- 旧文章 URL、sitemap 和外部链接继续有效。

如果注册表中的 Slug 与现有内容目录不一致，`sync_sections.py` 必须拒绝生成并报告冲突，禁止静默移动文章或改变 URL。

## CMS 防错设计

板块管理字段提供简洁的填写说明和前端校验：

- 名称不能为空；
- Slug 提供 `travel`、`reading-notes` 等格式示例，并校验小写英文、数字和短横线格式；
- 排序字段只接受整数；
- 重复 Slug、非法 Slug 和会改变已有目录的 Slug 在构建时再次拦截。

文章编辑页保留结构化字段校验和安全默认值：日期使用统一格式，草稿默认关闭，板块只能归属已注册板块。正文区域不增加额外 Markdown 或 LaTeX 示例，避免编辑界面过于拥挤。

## MathJax 预览性能设计

保留当前可测试的 `static/admin/mathjax-preview.js` 控制器，并调整调度策略：

- 发现预览内容变化后启动约 500ms 的 debounce；
- debounce 期间持续输入只更新最新快照，不启动新的 MathJax 扫描；
- debounce 结束后使用 `requestIdleCallback` 执行，浏览器不支持时使用带超时的 `setTimeout` 兜底；
- 同一时间最多有一个 `typesetPromise`；
- 渲染期间只保留最后一次变化，完成后最多执行一个合并的后续渲染；
- 内容快照未变化且上次渲染成功时不重复扫描；
- MathJax 尚未加载或渲染失败时保留重试状态；
- iframe 预览继续保持配置脚本先于 CDN 执行的顺序；
- 预览节点消失后回到空闲轮询，不持续高频占用 CPU。

这套策略减少整篇文章被反复扫描的次数，不改变最终公式结果，也不引入手动渲染步骤。

## 测试与验收

新增或更新以下测试：

### 板块同步测试

- 合法注册表生成正确的板块首页、导航排序和 CMS 集合；
- `acgn` 改名为“随笔”时目录和 URL 保持 `acgn`；
- 新增板块生成对应首页和文章集合；
- 重复、非法或会改变既有目录的 Slug 被拒绝；
- 无效排序和缺失名称被拒绝。

### CMS 编辑测试

- 生成的字段包含统一默认值和必要校验；
- 现有数学和随笔文章仍映射到原目录；
- 板块名称同步出现在 CMS 集合标签和 Hugo 生成页面。

### MathJax 测试

- 快速连续编辑只触发一次最终渲染；
- 延迟渲染期间只合并最后一次更新；
- MathJax 延迟加载后，在内容不变时仍会重试；
- 临时渲染失败后会重试；
- 无预览节点恢复为空闲轮询；
- iframe 配置加载顺序和替换 iframe 行为保持不变。

### 集成验收

- 运行 Python、Node 和 Worker 全量测试；
- 运行内容校验和板块同步；
- Hugo 构建 `/`、`/math/`、`/acgn/`、新板块页面和 `/admin/`；
- 确认文章 URL、sitemap 和公开 MathJax 加载范围没有回归。
