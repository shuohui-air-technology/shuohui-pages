# Obsidian 式写作编辑器与公开链接兼容设计

日期：2026-10-08（Asia/Shanghai）

状态：设计草案，等待用户审阅；不表示实现、测试或上线完成。

核对基线：`b2f0f5a038a0911bc44332e10f7fb500bc9764cd`。设计时远端 `main` 与此提交一致。

## 1. 已确认的目标与约束

用户希望后台不再像臃肿的富文本表单，而是尽可能接近 Obsidian 的实际写作体验。这里的“接近”指单栏实时预览、源码可见可编辑、简洁界面、公式与图片就地显示、折叠和可撤销的输入辅助，不是只更换配色。

已确认要求：

- 默认在同一正文区域编辑并看排版效果，不以左右分栏作为主体验。
- 保留列表续接、括号配对等输入辅助，允许关闭，支持撤销。
- 取消正文在富文本与 Markdown 间的往返转换，取消保存时未经确认的正文改写。
- 已有文章正文、文件位置、图片路径、发布日期、草稿状态和公开链接不得因更换编辑器而被批量修改。
- Slug 指公开分享网址中的文章路径段；允许已有网址使用的下划线 `_`，同时允许短横线 `-`。
- 有大量 LaTeX 的长文仍能流畅输入，不能每次输入都重新排版全文。

设计选择：保留 Hugo、PaperMod、Sveltia CMS、现有 GitHub 登录与提交发布链路，替换正文编辑组件并收敛写作界面。新后台不是完整的笔记工作台。

非目标：关系图、插件市场、多文章多标签工作区、Obsidian 插件兼容层、全文协作、改换托管平台、改变板块 Slug、改动本次范围以外的日期时区语义。Obsidian 主程序不是本项目可直接复用的开源实现；复用开源编辑器基础，独立实现相近交互。

## 2. 当前链路与问题边界

当前正文由 `scripts/sync_sections.py` 生成 `widget: markdown` 字段。`static/admin/index.html` 加载未锁版本的 Sveltia CDN、保存前格式化脚本和 MathJax 预览控制器。

`static/admin/markdown-format.js` 的 `preSave` 会改写正文，例如把 `说明：` 转成三级标题，把 `1.正文` 转成二级标题，并修复围栏、删除疑似表格行之间的空行。开启公式选项也不等于完全不改正文。

部署流程还运行 `scripts/content_tools.py normalize content`，会在构建工作区再次改写部分正文。只停止浏览器中的格式化不能保证最终公开页面按照作者的原文排版。

文章 Slug 的浏览器与 Python 校验均拒绝 `_`，但 Slug 留空时 Hugo 沿用文件名，已生成带 `_` 的正常网址。当前显式 Slug 冲突检查也不是所有实际路由、文件名回退路由和历史别名的统一检查。

这些是已核对的代码行为。中文输入丢字、光标移动等具体问题尚未完成真实输入法复现，不将它们全部归因于富文本转换。

## 3. 写作界面

### 3.1 两种工作状态

文章管理仍使用 Sveltia，正文组件提供“写作”与“文章属性”两种状态：

- 写作状态：正文为主体，默认单栏实时预览；顶部只保留模式切换、文章属性、CMS 原有保存/发布入口和状态。保留原生保存控件，不另造依赖内部状态的提交按钮。插入图片、折叠内容等收进简短菜单；大纲可展开，默认不挤占正文。
- 属性状态：展示原有标题、发布日期、公开链接名称、公式开关、草稿、评论、封面等控件；返回写作后恢复正文位置、选区和撤销历史。
- 源码模式：显示全部原始符号，保留相同的文档状态和撤销历史；模式切换不是一次正文修改。
- 阅读模式：只读排版，用于检查发布前的效果；切换时不导出或重新生成正文。

原有字段继续位于文章 front matter 顶层，不把它们移入一个嵌套 `properties` 对象。单个自定义字段的 `onChange` 仅控制自己的值，不能假定它能修改所有兄弟字段。属性编辑沿用 CMS 控件；界面收拢由独立、可撤回的布局适配层负责，不伪造输入事件修改数据。

布局适配限定在文章编辑页，锁定所验证的 CMS 版本，并检查目标控件是否存在。检查失败则显示正常 CMS 属性表单和源码编辑器，不能隐藏保存按钮、校验错误或发布菜单。不能依赖易变的生成类名，也不能卸载后重建控件来切换状态。

进入已有文章的编辑页时默认提供写作状态；若必填属性无效，明确展示错误和属性入口，不让被收拢的控件导致“保存没有反应”。首次新建文章可先填写必要属性再进入写作。小屏幕不强制显示侧栏。

### 3.2 接近 Obsidian 的正文行为

以 CodeMirror 的文本状态为唯一正文，利用语法树、装饰和预览部件实现显示：

- 选区或光标涉及的语法单元露出源符号，不吞掉标记、反斜杠或换行。
- 非活跃区域显示标题、强调、链接、图片、公式、代码块、表格的排版。
- 对块级表格、公式、代码及折叠区域，进入编辑时显示完整的相应源码块；点击预览能够回到对应源码位置。
- 支持当前 `{{< collapse summary="…" >}}` 与闭合标签，沿用默认折叠及 `openByDefault` 的含义；折叠状态仅是界面状态。
- 未闭合围栏、正在输入的公式和未知短代码保持可编辑源码，不能清空或“自动补成另一种内容”。
- 多行选区、键盘移动和复制操作不得跨过不可达的隐藏内容。纯文本复制返回对应 Markdown；需要复制排版文本时提供显式操作，不能静默改变剪贴板语义。

不承诺与 Obsidian 每个快捷键、插件或像素完全一致。本项目的 Hugo 短代码及发布属性需要自己的适配，不能为追求外观而损坏这些功能。

## 4. 模块和数据流

模块职责分开，生产运行只加载本地构建好的必要资源：

1. `document-state`：CodeMirror 状态、选区、历史、IME 状态与外部值同步；唯一正文写入接口。
2. `live-preview`：识别语法和源码区间，构建显示装饰，处理点击定位；无正文写入权限。
3. `markdown-preview`：阅读模式渲染及消毒，兼容数学分隔符和 collapse 短代码；不把 HTML 导回 Markdown。
4. `math-scheduler`：按可见区域加载、缓存和排队渲染公式；无正文写入权限。
5. `cms-adapter`：注册字段、传递 CMS 值、处理图片和生命周期；不调用未公开的 CMS 数据存储接口。
6. `layout-adapter`：写作/属性布局与降级，保留原有表单控件。
7. `public-route`：公开链接预览、校验、历史链接保护；与正文处理解耦。

读取：仓库文章 → CMS 的原字段 → 文本状态。输入或显式辅助操作 → 文本事务 → CMS `body` 值。文本状态 → 显示装饰/阅读视图，只单向读取。保存 → CMS 原有提交链路，不经过预览反向序列化。

采用 `CMS.registerFieldType` 注册独立正文类型，在调用 `CMS.init()` 前完成注册。使用手动初始化，锁定验证过的 Sveltia 版本。CodeMirror 及渲染依赖放在独立的编辑器构建目录，精确锁版本；生成的静态资源、许可声明和构建检查随仓库维护。实施时再选择并验证具体依赖版本，本设计不要求安装依赖。

CMS 支持自定义字段、`value/onChange`、媒体接口及初始化顺序，依据：[字段 API](https://sveltiacms.app/en/docs/api/field-types)、[手动初始化](https://sveltiacms.app/en/docs/api/initialization)。

## 5. 输入与原文保护

原文保证针对 Markdown 正文，不要求 CMS 把 front matter 的引号风格等序列化细节逐字保留；字段值、未知已有字段和媒体引用必须保留。没有正文操作时，正文的反斜杠、空格、换行及尾部换行逐字一致。支持常见 LF/CRLF 文件，不静默统一换行风格。

外部 `value` 与本地文档相同时不重建编辑器。确有外部内容变化时进行有来源标记的同步；与本地未保存编辑冲突则提示，不直接覆盖。退出写作、切换属性和切换预览不得清空撤销栈。

`compositionstart` 到 `compositionend` 期间暂停当前块的预览结构切换，不用异步渲染替换输入 DOM，也不在组词期间自动配对或续接。结束后根据最新文档更新显示，旧的异步结果不得覆盖新输入。

输入辅助默认开启，设置保存在本浏览器而非文章正文：

- 列表续接只发生在列表中明确按 Enter 时；空列表再次 Enter 退出列表。
- 配对适用于括号、方括号及明确的 Markdown 配对；代码、转义和选区的行为分别测试。美元符号默认不盲目补成公式，防止把金额识别成数学。
- 每次辅助与当次输入构成可撤销事务；可关闭列表续接和配对。
- 不运行“看起来像标题/段落”的自动推断，不自动把 `_` 改成 `-`。

保存前移除现有正文格式化 hook。允许保留字段/链接的校验和作者主动触发的图片 URL 替换；不能借“校验”改写正文。发现可疑格式只显示可定位提示，不自动修复、不加入长篇示例说明，也不因一个未完成的普通 Markdown 标记禁止存稿。

图片选择/上传继续使用 CMS `pickFile/addFile` 和原来的媒体位置，不另建上传服务。作者主动插入的新图片暂存 URL 可在保存时由 CMS 换成最终地址；这是显式插入操作的完成，不是任意改写。失败保留文字、选区和可重试入口，不能插入失效地址。粘贴普通文本保留原文，不做富文本清洗后回写。

## 6. 预览准确性、异常与响应速度

Markdown 解析配置与现有 Hugo Goldmark 的已启用语法对应。数学在 Markdown 转义处理前被识别和保护，代码块中的公式/短代码不执行；金额、转义美元符号、行内公式及独立公式分别测试。未知 HTML 和短代码退回可见源码，预览 HTML 消毒，不能执行脚本或危险协议。

保留现有 MathJax 3.2.2 与公式配置；自定义正文预览由新的调度器单独管理。旧的全局预览轮询不得同时扫描新编辑器，避免双重排版。网站前台现有公式与两行摘要渲染不因后台替换而重写。

编辑显示先更新轻量语法装饰；图片和公式以可见区加有限预加载边界为单位调度。公式排版采用约 500ms 停顿合并、空闲调度和单一队列，优先当前视窗；语法或配置不变的公式复用结果，缓存有容量限制。过期结果按文档版本丢弃，不阻塞输入，不渲染已卸载节点；离开文章取消任务并清理监听器。

数学渲染失败保留源码并提供轻量提示/重试，不阻止保存。资源或编辑器初始化失败退回原文输入框，禁止退回会重新序列化正文的富文本模式。降级时显示原因，不让字段空白或保存空正文。

性能验收固定测试环境并留记录：本机当前 Chrome、桌面宽度约 1440px、CPU 不限速；使用现有最长文章和至少 15 万字符/2000 个公式的合成测试。连续输入 30 秒、滚动、切换模式后，输入事件到下一帧显示延迟 p95 不高于 50ms，且不能有预览造成的超过 200ms 的持续卡住。记录包体、首开时长、长任务、排版次数和输入延迟；达不到就优化或减少预加载，不以“单测通过”替代运行测量。

初始资源目标为编辑器专属 JS 压缩传输量不超过 300KB，数学与重型代码语言包延迟加载；共享 CMS 本体单独统计。大段代码不在每次输入时做全语言高亮。若明确无法达到资源目标，必须在实施验收报告中解释并重新征得取舍同意，不能静默增加功能。

## 7. 部署排版与旧文章兼容

不能直接删除部署规范化而假定旧页面不变，也不能继续对所有新正文猜测标题。

采用有限、内容寻址的旧排版兼容层：

1. 实施前在临时目录按当前完整部署链路构建基线，记录每篇当前公开文章的原始正文、有效公式配置的摘要、实际公开路由和正文 HTML；不在用户原 checkout 运行写入型规范化。
2. 对当前公开正文与旧部署规范化结果不同的文章，记录原始内容 SHA-256 和已经确定的兼容 Markdown。草稿没有待保留的公开排版，不写入可供前端读取的兼容结果。该记录不含凭据，不重新推断任何后来的正文。
3. 新构建链路先在临时内容目录准备文章，不再对仓库 `content/` 做正文改写。只有路径、原始正文摘要和影响排版的配置都与基线匹配时，才使用冻结的兼容结果，保留未改旧文章的公开排版。
4. 新文章和已经主动修改正文的文章按作者实际 Markdown 渲染，不套用旧标题/分段猜测规则。修改标题、日期或 Slug 本身不会让未改正文失去兼容。
5. 对命中旧兼容记录的文章，阅读模式可读取同一冻结结果；开始修改正文时给出一次简洁提醒：“本篇原有自动排版将不再套用，请检查发布预览”。编辑模式仍保留真正的源码，不将兼容结果灌回文本状态。
6. 原有日期和结构校验保留，但变成验证优先；确需准备构建值时只在临时目录中处理。非法必填字段报告错误，不静默更正作者选择。

这层兼容记录只覆盖迁移基线，是为避免一次后台升级改变全站旧排版，不是另一套长期自动格式化。旧文章正常编辑后可逐步退出，无需批量改写源文档。

## 8. 公开分享链接

### 8.1 字段与预览

继续保存文章 front matter 的 `slug`，标签改为“公开链接名称”；不使用 CMS 外层 entry slug 代替 `data.slug`。旁边显示完整的预计网址，并区分“已保存到仓库”和“已部署”。没有部署成功证据时不得显示“已经上线”。原生发布入口及其跳过 CI/触发 CI 的行为保留，不改成每次输入自动提交。

新的显式值允许小写英文、数字、单个 `_` 或 `-` 分隔符，规则为 `^[a-z0-9]+(?:[-_][a-z0-9]+)*$`。不能输入域名、斜杠、查询参数或目录穿越，也不自动替换作者的符号。留空沿用实际文件名；已有中文文件名的回退网址继续兼容，不要求所有旧文件改为英文。

完整预计网址从实际板块路径、文章路径规则和 slug 计算。发布后由固定版本 Hugo 的内容清单及输出检查确认，不能只根据字段字符串宣布链接有效。特殊 `url`/permalink 配置若以后出现，必须显示其优先级并禁用不生效的 Slug 编辑，不隐藏冲突。

后台与 Python 校验采用同一组一致性样例。新增板块的配置从生成器统一获得字段和正文编辑器，不手改生成后的 `config.yml`。板块 Slug 保持现有规则和稳定性要求，本次只放宽文章 Slug。

### 8.2 历史链接与冲突

旧链接保护使用 Hugo aliases 生成静态跳转页；GitHub Pages 上这是客户端跳转，不宣称是 HTTP 301。[Hugo URL/aliases 说明](https://gohugo.io/content-management/urls/#aliases)。

不依赖从当前输入值反推“原 Slug”，也不依赖浏览器缓存一定代表已保存状态。采用版本化路由历史：

- 以文章仓库路径为稳定身份，基线记录当前公开路由；以后从基线到当前提交的 Git 历史提取该路径上的有效 Slug 改动。为保证中间已分享链接不被遗漏，可保留期间所有非草稿版本的路由；这不等于声称每个中间提交实际部署过。CI 使用完整所需历史，不能在历史不足时悄悄跳过保护。后台变更 Slug 不重命名文件；外部文件重命名须显式关联原身份，否则构建报错，不猜测两个不同文章是同一篇。
- 每次构建在临时内容中合并原有 `aliases` 与历史路由，去重、去掉当前 canonical 地址；不写回作者的正文或批量重命名文件。
- A → B → C 时，A 与 B 均直接指向 C，不形成多次跳转；撤回到 A 时删除 A 的自跳转并保留其他有效旧地址。
- 只为当前公开文章输出跳转；草稿不生成正文、别名页或 sitemap 项，防止旧链接泄露草稿。已发文章转为草稿后的旧 URL 不保证继续可访问，这是隐藏文章的预期行为。
- 合并冲突检查覆盖显式 Slug、留空文件名回退、已有 aliases、历史 aliases、板块首页及保留系统路径；不能只查两个显式 Slug 是否相同。
- 确认别名占用另一个当前有效页面时中止构建，不覆盖另一篇文章；提示具体两个来源和地址，交由作者选择，不擅自夺回旧路径。

生成的后台路由预览清单只含当前公开文章的稳定标识、canonical 路由与别名，不公开草稿正文/标题或凭据。浏览器可以据此提前提示与现有公开页的冲突，但不能据此保证没有未部署文章或并发编辑的冲突；构建基于完整最新内容做最终检查。它用于提示旧公开网址，不保证反映尚未部署的仓库变化。任何首次基线生成和后续记录生成都可重复执行，结果必须确定。

## 9. 代码边界与验证交付

实施预计涉及独立编辑器源码/依赖锁、`static/admin/` 本地资源及入口、CMS 配置模板/生成器、内容校验与临时内容准备、路由记录和别名检查、GitHub 构建流程、README 与相关测试。

不修改 OAuth Worker 权限或凭据，不搬动用户原仓库，不把缓存或生成页面提交到 Git。布局层、预览层、保存层分别测试；组件出错能单独降级。源码与生成 bundle 的一致性纳入 CI，避免改源码却部署旧脚本。

发布前必须通过以下验收，不能仅凭构建成功宣称完成：

- 对所有已有正文执行打开、不编辑、切换模式、保存 round-trip 检查；除作者主动插入新媒体的最终路径替换外，正文逐字一致。
- 只改元数据时正文不变；未知已有 front matter 字段不丢失；文件路径、发布日期、draft/math/comments 值保持原语义。
- 中文 composition 事件、候选提交、取消组词、粘贴、跨块选择、撤销/重做、关闭辅助、来回切换属性/正文，在真实浏览器中验证；合成事件测试不得冒充真实 macOS 输入法测试。没有完成真实输入法验证必须明确报告，不能宣称已消除该类问题。
- `_` 和 `-` Slug、留空回退、重复 canonical、canonical/alias 冲突、A→B→C、撤回 Slug、旧地址跳转、草稿旧地址消失均有测试。
- 现有 Agent、提示词工程和最长数学文章作为固定回归样例；检查公式内容、表格完整行、代码围栏、collapse 短代码和正文/标题层级。
- 改造后的基线构建对所有未改文章比较路由与正文 HTML；时间戳等非语义生成噪声之外不能出现差异。旧排版兼容与新文严格原文行为分别测试。
- 新建一个临时板块验证其自动获得新编辑器和公开链接字段，测试完成不改正式注册表。
- 大量公式压力测试达到第 6 节指标，保存失败、媒体失败、渲染失败、资源加载失败不会丢失正文；浏览器无未处理异常。
- 发布前检查真实浏览器中的输入与渲染；只有用户随后授权推送/部署，才验证正式站部署结果与实际公开链接。设计审阅不等于授权上线。
