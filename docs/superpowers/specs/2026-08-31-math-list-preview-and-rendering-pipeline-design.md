# 数学列表预览与渲染管线加固设计

## 背景与诊断

`/math/` 列表卡片当前会显示原始 LaTeX 定界符，进入单篇文章后才正常渲染。生成结果证明这不是文章内容错误：数学文章均显式设置 `math: true`，单篇页面也会加载共享配置和 MathJax 3.2.2。

根因位于配置传播和页面级加载判断之间：

1. `data/sections.json` 已为数学板块声明 `math: true`；
2. `scripts/sync_sections.py` 生成 `content/math/_index.md` 时没有写入该字段；
3. `layouts/partials/extend_head.html` 只检查当前页面的 `.Params.math`，不会检查列表中的子文章；
4. PaperMod 列表模板通过 `.Summary | plainify` 输出摘要，公式定界符仍在 HTML 文本中，但列表页没有加载 MathJax；
5. 当前 `/math/` 一页有 10 张卡片，生成 HTML 中包含 158 个 `$$` 定界符，直接对全页进行同步公式处理会带来不必要的首屏工作。

另有两个相关工程缺口：CMS 入口目前无条件下载 MathJax，即使正在编辑不含公式的文章；Pages 工作流执行构建检查，但没有正式运行已有的 Python 和 Node.js 全量测试。

## 目标

1. 用户不进入文章，也能在 `/math/` 两行摘要中看到已渲染的公式。
2. 卡片继续保持现有两行摘要高度，块级公式不得撑高列表卡片。
3. 只渲染视口附近的公式，避免列表页一次处理全部表达式。
4. 新增板块、重命名板块或在普通板块中单独启用数学文章后，不再出现相同的局部缺脚本问题。
5. CMS 连续输入时保持流畅：停笔约 500 ms 后自动渲染，只处理最新快照，同一时间最多一个渲染任务。
6. 不含公式的页面和编辑会话不下载 MathJax 主包。
7. 将关键加载范围、配置传播和输出行为纳入 CI 与部署后烟雾验证。

## 非目标

- 不更换 MathJax，不引入 KaTeX 或第二套数学引擎。
- 不改变文章 URL、板块 Slug、正文内容、公式语法或摘要行数。
- 不要求作者手工填写摘要或插入 `<!--more-->`。
- 不增加“手动渲染公式”按钮，不在正文编辑区加入格式示例。
- 不固定或降级当前 Sveltia CMS 版本。
- 不在本次工作中改造 PaperMod 的全部列表模板或站点视觉风格。

## 约束与性能预算

- MathJax 继续固定为 `3.2.2`，定界符继续支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。
- `/` 和没有数学文章的普通板块不得加载 MathJax。
- 每个浏览上下文最多注入一次主 MathJax 运行时；失败后可以重试，但不得并发重复注入。
- 列表首屏只处理进入 `lazyMargin` 范围的公式；未滚动到的卡片不应抢占首屏公式排版时间。
- CMS 防抖窗口使用约 500 ms；连续输入只保留最后快照；已有的 idle 调度、单飞渲染、失败重试和 `stop()` 清理语义必须保留。
- 桌面和移动端列表摘要继续使用两行截断，公式输出不能突破卡片边界。

## 方案选择

### 未采用：只在数学板块首页写入 `math: true`

这一方案可以修复当前 `/math/`，但普通板块中单篇文章覆盖为 `math: true` 时仍会失败，并且缺少懒渲染和 CI 防线。

### 采用：配置传播、内容检测和懒渲染三层防线

该方案保留现有 Hugo、PaperMod、Sveltia 和 MathJax 架构，只补齐数据流断点，并在共享配置、列表样式、CMS 加载器和构建检查处建立相互独立的防线。

### 未采用：构建时预渲染公式

服务端预渲染可以减少客户端工作，但需要新增 Node 数学构建链或第二套渲染器，还会增加与 CMS 预览结果不一致的风险。本项目规模下收益不足以抵消维护复杂度。

## 架构设计

### 1. 板块配置传播

`data/sections.json` 继续作为板块唯一事实来源。`render_section_index()` 在生成 `content/<slug>/_index.md` 时写入显式布尔值：

```yaml
math: true
```

或：

```yaml
math: false
```

该字段同时表达板块中新文章的默认数学能力和板块列表的默认渲染需求。`sync_sections.py --check` 会继续检查生成结果，防止注册表、板块首页和 CMS 配置漂移。

### 2. 公共页面的 MathJax 需求判定

`layouts/partials/extend_head.html` 使用一个清晰的布尔判定：

1. 当前页面 `.Params.math` 为真时加载；
2. 全局 `site.Params.math` 为真时加载；
3. 当前页面是 section 且任一普通子文章显式 `math: true` 时加载。

第三条用于覆盖混合板块场景，避免以后新增板块后再次依赖某个生成字段才能工作。首页不会因为站点其他位置存在数学文章而加载 MathJax。

满足条件时依次加载共享配置与固定版运行时；不满足时不生成相关 `<script>` 标签。

### 3. 列表公式的懒渲染和两行布局

共享 `static/js/mathjax-config.js` 加载 MathJax 3.2.2 官方 `ui/lazy` 扩展，并设置适度的预渲染边距，使即将进入视口的公式提前完成排版。

列表页继续使用 PaperMod 当前摘要文本和两行 `line-clamp`。项目 CSS 仅针对 `.list .entry-content` 中的 MathJax 输出覆盖块级公式的外边距、内边距和块布局，使摘要中的 `$$...$$` 以紧凑预览形式参与两行截断。单篇正文中的块级公式仍保持居中、独占一行和横向滚动。

不在模板层截断 LaTeX 字符串，避免产生缺少闭合定界符的表达式。Hugo 自动摘要仍作为内容来源，CSS 负责视觉截断。

### 4. CMS 按需加载与编辑调度

CMS 保留现有预览控制器和状态机，不重新设计编辑器：

- 轮询只负责捕获最新节点、模式和文本快照；
- 内容变化后使用约 500 ms 防抖；
- 防抖结束后使用 `requestIdleCallback`，不支持时使用带上限的定时器；
- 同一时间最多一个 `typesetPromise`；
- 渲染期间发生多次变化，只执行一个合并后的最新任务；
- 未变化且上次成功时不重复渲染；
- 失败或 MathJax 尚未准备好时保留重试状态。

新增按需运行时加载边界：

1. `static/admin/index.html` 不再无条件加载 MathJax 主包，只加载轻量共享配置和预览控制器；
2. 控制器检测到预览中存在完整的受支持数学定界符后，才为主文档注入固定版运行时；
3. 同一文档使用 `idle / loading / ready / failed` 状态防止重复注入；
4. iframe 继续先注入共享配置，再注入固定版运行时，并对替换后的新 iframe 单独处理；
5. 普通文章没有完整公式定界符时，不下载 MathJax；
6. 本地脚本和共享配置引用使用新的发布版本参数，避免部署后浏览器继续复用旧实现。

定界符检测只决定是否加载运行时，不负责解析或改写公式；最终语法识别仍由 MathJax 完成。

### 5. CI 和生成产物防回归

`.github/workflows/hugo.yml` 在构建前正式运行：

- Python 全量测试；
- MathJax、Markdown 格式化和 Worker 的 Node.js 全量测试。

现有 `check_build.py` 扩展数学资源检查：

- 注册表中 `math: true` 的板块首页必须引用共享配置和固定版运行时；
- 注册表中 `math: false` 且无数学子文章的板块不得误加载；
- 首页继续不得误加载；
- 数学文章页面继续必须加载；
- 所有本地脚本引用仍必须对应真实构建文件。

`sync_sections.py` 测试覆盖 `math` 字段写入和生成文件漂移，防止以后新增板块时只更新 CMS 默认值而漏掉 Hugo 页面参数。

## 数据流

```text
data/sections.json
        |
        v
sync_sections.py
  |                    |
  v                    v
section _index.md      CMS config.yml
  |                    |
  v                    v
Hugo section page      Sveltia editor
  |                    |
  +---- needsMath -----+---- delimiter detection
             |
             v
shared MathJax config (3.2.2 + ui/lazy)
             |
        +----+----+
        v         v
two-line list     debounced CMS preview
```

## 错误与降级行为

- MathJax CDN 暂时失败时保留原始 LaTeX 文本，页面链接和正文仍可访问；CMS 控制器记录警告并在后续轮询中重试。
- `ui/lazy` 加载失败不得导致 Hugo 页面脚本报错循环；固定运行时仍由同一个加载状态管理。
- section 生成文件缺少或错误的 `math` 值时，`sync_sections.py --check` 和测试必须在部署前失败。
- 构建页面缺少应有的 MathJax 资源或非数学页面误加载时，`check_build.py` 必须返回非零状态并指出具体页面。
- 浏览器不支持 `requestIdleCallback` 时继续使用已有定时器兜底。
- 视觉规则不支持 `line-clamp` 的浏览器仍通过 `overflow: hidden` 保持卡片边界，不允许公式覆盖元数据或其他卡片。

## 测试设计

### Python

- 数学板块生成的 `_index.md` 包含 `math: true`；普通板块包含 `math: false`。
- 新增第三个数学板块后，同步结果和 CMS 默认值一致。
- 手工删除或修改生成的 `math` 字段时，`--check` 报告 drift。
- 构建检查能够区分：数学 section 正确加载、数学 section 漏加载、普通 section 误加载、数学单篇正确加载。
- 工作流测试证明 Python 和 Node 全量测试位于 Hugo 构建之前。

### Node.js

- 共享配置启用 `ui/lazy` 并保留四组定界符。
- 完整数学定界符触发按需加载；普通货币符号、孤立 `$` 和代码文本不触发。
- 主文档运行时并发请求只注入一次；失败后允许重试。
- iframe 保持“配置成功或失败后再加载运行时”的既有顺序。
- 连续输入只渲染最新快照；500 ms 防抖、idle 兜底、单飞、失败重试和清理行为全部保持。

### Hugo 与浏览器集成

- `/math/` HTML 包含共享配置和固定版 MathJax；`/` 与 `/acgn/` 不包含。
- `/math/` 第一张卡片不进入文章即可看到已排版公式。
- 桌面和移动视口的摘要均保持两行，卡片元数据位置不跳动。
- 向下滚动时后续卡片公式在进入懒渲染边距后完成排版；离屏公式不在首屏阶段全部生成 MathJax DOM。
- 单篇文章的块级公式仍独占一行并可横向滚动。
- CMS 编辑普通文章时不请求 MathJax；打开已有数学文章后仅请求一次；快速连续输入后最终公式与最新文本一致。

## 发布与验收

1. 实现前重新确认分支包含 `origin/main` 最新内容，禁止覆盖用户新增文章和图片。
2. 每个行为遵循测试先行：先观察失败，再写最小实现，再运行相关及全量测试。
3. 使用独立子代理分别做规格符合性和代码质量复审；主代理逐项核对，不直接采信结论。
4. 运行 Python、Node、内容规范化、内容校验、Hugo、生成产物检查和 `git diff --check`。
5. 使用真实浏览器验证桌面、移动、列表滚动和 CMS 编辑场景，并记录网络请求与控制台错误。
6. 推送 `main` 后持续监控 GitHub Actions；若失败则继续修复和重新验证。
7. 线上验证 `/math/` 公式预览、两行高度、普通页面加载范围和后台编辑体验。
8. 将最终架构、测试数量、提交和部署结果同步到项目主目录中的本地内部汇总文件；该文件保持未跟踪，不进入部署提交。
